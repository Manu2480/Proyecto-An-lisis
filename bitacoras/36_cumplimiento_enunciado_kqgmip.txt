Bitácora 36 — Cumplimiento estricto del enunciado K-QGMIP
==========================================================
Fecha: 13/06/2026

Contexto
--------
Tras completar el benchmark rápido n=25 (bitácora 35), se revisó el código contra
las exigencias del proyecto (docstrings, API pública, tests de equivalencia k=2,
evaluación de particiones). Se aplicaron los ajustes pendientes sin re-ejecutar
benchmarks.

Cambios en kpartition.py
------------------------
1. Docstrings completos en métodos clave:
   - Módulo y clase KPartitionSIA (ya existían, se mantuvieron).
   - find_k_partition(), aplicar_estrategia(), _resolver_k_partition().
   - _construir_tabla_costos() — nuevo helper que encapsula find_mip + tabla.
   - _heuristica_greedy(), _k_partir(), _reconstruir_tensor(), _evaluar_particion(),
     _fmt_kparticion().

2. API pública find_k_partition():
   - Método principal de búsqueda heurística k-MIP.
   - aplicar_estrategia() delega en _resolver_k_partition() (misma lógica).

3. Refactor menor:
   - Bloque duplicado de preparación geométrica movido a _construir_tabla_costos().

Nota para el informe
--------------------
- k=2 con heurística por defecto delega en GeometricSIA (bipartición exacta).
- k≥3 usa heurísticas (Greedy, KL, MCTS, KL+MC-EMD); no garantiza óptimo global.
- _evaluar_particion usa emd_efecto sobre marginales 1D (equivalente al producto
  tensorial bajo independencia condicional); _reconstruir_tensor expone el producto
  explícito y se valida en tests.
